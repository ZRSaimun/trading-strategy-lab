# Loop 4 — disconnected multi-currency paper liability stress

`backend/app/paper_fx_liability_guard.py` addresses a dangerous accounting assumption: USD-denominated CFD or stock scenarios cannot be summed directly with GBP account equity, margin and daily-loss limits. This **offline, read-only** evaluator accepts exact-schema owner-declared account/exposure/FX quote data and requires one direct `SETTLEMENT/ACCOUNT` currency quote per non-account currency. Missing, reversed, ambiguous or extra pairs never silently disappear.

For each declared loss, gross notional and reserved margin, it uses the **FX ASK** multiplied by `(1 + fx_shock_bps / 10000)` as a conservative conversion. It never uses the mid price, nets gains or assumes a favorable FX conversion. Quotes are rejected for stale or future timestamps, transport lag, crossed/excessive spreads, non-advancing declared sequences or repeated quote IDs. Open and pending liabilities count in full; unknown/cancel-pending states force reconciliation. Account-wide loss, single-position loss, daily loss, stressed-equity leverage/margin and emergency-circuit checks must all pass even for an unverified review.

**No trading capability is added.** `REVIEW_ONLY_UNVERIFIED` only describes internal arithmetic and cannot authorize paper/demo/live orders. The caller-supplied FX quotes, positions, previous sequence and clock are not authenticated. The SHA-256 diagnostic is not a signature or replay registry. The risk figures are a scenario, not guaranteed fills, stop protection, broker free margin, liquidation estimates or a statement of profit. Account-currency cash losses are treated as already denominated; an actual provider must verify contract specifications, fees, financing, tiered margin, multi-currency balances and real FX conversion. The one-way direct-pair restriction deliberately excludes inverse/triangulated conversions until independently validated. No credentials, network requests, persistence or charges.

Run synthetic tests from `backend` with `PYTHONPATH=. python -m pytest -q tests/test_paper_fx_liability_guard.py`. Before integration, require authenticated broker inventory, executable FX quotes and durable sequence checkpoints, persistent atomic reservations and daily-loss latches, duplicate-order quarantine, a fresh order-specific human review, PostgreSQL concurrency/crash recovery, and production backup/rollback and health verification.

Broker scope: Trading 212's public API (https://docs.trading212.com/api) supports Invest/Stocks ISA only, **not CFD execution**. It also states API order execution is in the primary account currency and API multi-currency accounts are not supported. This offline FX review is not an adapter for Trading 212 CFD orders, nor a claim that the API returns native foreign-currency liabilities.
