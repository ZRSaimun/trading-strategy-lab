# Disconnected durable forecast-review outbox (Loop 5)

`backend/app/forecast_alert_outbox.py` is a server-side **persistence and concurrency primitive only**. It uses the existing `Record` and `Audit` tables; there is no migration, route, scheduler, network notification, broker adapter or live order capability. A caller must authenticate/authorize its user and source separately. This module never sends messages or trades.

The queue operation validates a *persisted, still-pending* exact-identity forecast in the transactional forecast journal. Its server-owned expiry is the earlier of the requested age budget and the target candle close. One deterministic record key per session/forecast prevents repeated queueing. The claim operation atomically moves `QUEUED` to `IN_FLIGHT_UNCERTAIN` before any hypothetical send, and issues a random one-use claim ID. After a crash or timeout, this state **cannot be automatically retried or cancelled**: an external transport could have delivered the message. Acknowledgments are recorded only as `ACK_RECORDED_UNVERIFIED`, never as proof of provider delivery. Only unclaimed, unexpired records can be cancelled. Reads expose expired unclaimed work as `EXPIRED_UNCLAIMED` without mutating history.

Record updates use compare-and-swap with a same-transaction audit insert. Content SHA-256 detects accidental corruption, **not malicious tampering** by a DB administrator. Concurrent-worker and process-kill PostgreSQL acceptance, authentic provider delivery receipts, transactional feed entitlement, source/server-clock trust, market-session handling and multi-instance end-to-end alert integration remain outstanding. There is no guarantee of exactly-once delivery: it prioritizes **at-most-one claim** and stops on ambiguous outcomes. Existing frontend replay alerts are not an unattended transport.

All outputs are disconnected and unauthenticated. Historical BID candles are not executable bid/ask quotes. `notificationEnabled=false`, `deliveryVerified=false`, `mayExecutePaperOrder=false`, `mayExecuteLiveOrder=false`. Synthetic tests prove local state-machine behavior only, not real notifications, forecast calibration, returns, or maximum drawdown. No production deployment until branch reconciliation, full exact-head CI, isolated PostgreSQL crash recovery, verified backup restoration, rollback and health checks.
