# Offline Twelve Data credit-header sequence review

`app.provider_credit_header_sequence.audit_twelvedata_credit_header_sequence(receipt_reports, declared_window_start_utc=..., declared_window_end_utc=...)` compares a bounded caller-supplied sequence of successful one-shot Twelve Data Gold receipts **without HTTP, file writes, credentials, subscriptions or orders**.

**UTC-minute reset correction (26 October 2026):** Twelve Data documents that API credits reset at the beginning of each minute. The caller's declared selection (up to 24 hours) is **not one continuous quota window**. The audit now compares credit counters **only** for adjacent responses in the same UTC minute when *both requests began and completed within that minute*. A cross-minute pair is excluded from monotonicity comparisons and counted as `utc_minute_transitions_not_compared`. A request that straddles a UTC-minute boundary is counted as `requests_crossing_utc_minute` and excluded from comparisons because the charged minute is not established by a response timestamp. Both situations force `REVIEW_REQUIRED`, not a fabricated counter contradiction or verified reset. A minute transition cannot be used to infer an account-wide reset or credit refund.

Within a comparable single minute, the audit checks duplicate request identities, source/protocol/side claims, timestamps, documented `api-credits-used` / `api-credits-left` response headers, counter decreases, increases in remaining credits, changes in the used-plus-left total, missing headers, tied response timestamps and unexplained credit deltas. Any anomaly returns `REVIEW_REQUIRED`; malformed or forged inputs fail closed. Even a clean same-minute series returns only `SELF_ATTESTED_SEQUENCE_ONLY`. The existing one-reservation-per-minute budget will normally make **multiple comparable local receipts impossible**, so do not interpret a multi-minute audit as a validated usage sequence.

**Critical limits:** The provider's actual quota reset windows, account/key identity, all other applications' requests, omitted or fabricated receipts, caching, credits charged on errors, provider billing, licensing, storage rights and entitlements are not independently verified. The series is not an account-wide census. A changed counter may indicate a reset or other legitimate activity, not misconduct; never automatically retry, refund, increase quotas or activate feeds based on this audit. For a local reservation population, separately run the read-only `provider_credit_receipt_census` on a quiescent private ledger. These two audits do not together prove independent account usage reconciliation.

Twelve Data documents its UTC-minute reset and Basic-plan midnight-UTC daily reset in its [credit guidance](https://support.twelvedata.com/en/articles/5615854-credits); its [API usage guidance](https://support.twelvedata.com/en/articles/5713553-control-over-api-usage) describes response headers and states that `/api_usage` itself costs one credit. Trading 212 documents its API for **Invest and Stocks ISA only, not CFDs**: https://docs.trading212.com/api. No broker connection or execution is implemented here.
