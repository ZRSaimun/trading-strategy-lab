# Offline holdout multi-authority quorum (Loop 3)

`frontend/lib/holdout-quorum-review.ts` is a disconnected, **fail-closed** research review. It requires a configurable quorum of **2–6 distinct pinned authority labels** to sign **both** (a) the exact commitment-only head (sequence 0), with a claimed anchor timestamp no later than the frozen protocol's validation end, and (b) the **final** audit-chain head. The full commitment and access chain, each Ed25519 signature and each receipt are revalidated. Signatures for earlier intermediate heads do not substitute for the final head.

Unlike the single-chain anchor verifier, the quorum reviewer verifies each co-signature independently, so different authorities can sign the same sequence without violating the underlying strict sequence check. Inputs are bounded to 10,000 audit entries, 12 signatures and 12 pinned keys because full-chain validation is repeated per signature. Larger histories require a separately reviewed batched verifier, not disabled bounds.

Example: `reviewHoldoutAnchorQuorum(commitment, entries, anchors, trustedKeys, 2)`. A passing result is deliberately named `QUORUM_CLAIM_TIME_UNVERIFIED`; insufficient signatures produce `INSUFFICIENT_QUORUM`, never an untouched-holdout certification. Duplicate same-key/same-head signatures, malformed or forged signatures, untrusted keys, recorded contamination and invalid thresholds fail closed. Two keys declaring the **same** authority count only once.

**Important:** The authority names and public keys are supplied by the caller. This code does **not** establish independent control of those keys, key revocation, timestamp truth, independent append-only storage, completeness of access logging, source authenticity, licensing, or an untouched holdout. A dishonest signer can backdate a signed receipt. The owner must authenticate distinct authorities and pin keys outside the research environment, independently attest receipt time, and audit retention and data access before treating the quorum as meaningful.

Run `cd frontend && node --experimental-strip-types --test tests/holdout-quorum-review.test.ts` with Node 22, then run full CI. No network, market-data reads, paid provider, production writes, live execution or broker integration is enabled. Do not merge or deploy without current-head CI and verified production backup, rollback and health readiness.
