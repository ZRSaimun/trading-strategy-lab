# Offline prospective forecast drift review (Loop 5)

`backend/app/forecast_drift_audit.py` is an **opt-in, disconnected** descriptive comparison of two preregistered, source-identical cohorts. It makes no database, network, notification, order, broker, or production changes. It accepts strictly shaped journal-derived records with exact feed identity, model version, 1/3/12 completed-candle horizon, base candle start, issuance time, resolution time, probability, and status (`PENDING`, `SETTLED`, `VOID_GAP`). It does **not** authenticate these caller-provided fields.

`audit_forecast_drift(records, identity=..., model_version=..., horizon=..., cutover_at=..., as_of=...)` uses a declared cutover. Reference outcomes must target and resolve no later than cutover; recent forecasts must have been issued on or after cutover. Cross-boundary observations are not scored. Only complete, nonoverlapping resolved outcomes are scored. Pending, gap-voided, late-reference, and overlap-excluded records count against coverage. Minimum 30 nonoverlapping settled outcomes per cohort and at most 10% censored by default; otherwise **INSUFFICIENT_OR_CENSORED** with no Brier delta. This is a conservative coverage gate, not proof that omitted records were reported.

The reported Brier difference is `recent mean((p-y)^2) - reference mean((p-y)^2)`; default `>= 0.05` produces `DRIFT_REVIEW`, otherwise `NO_THRESHOLD_BREACH`. The threshold, cohort cutover, sample budget and horizon must be **declared before observing outcomes**. This is a descriptive review trigger: dependent market returns, regime changes, selection, and repeated testing invalidate naive significance claims. No p-value, calibrated confidence, market edge or profitable expectancy is asserted. `sourceAuthenticated`, `recordCompletenessVerified`, `statisticalSignificanceEstablished`, `mayExecutePaperOrder`, and `mayExecuteLiveOrder` always return `false`.

Run isolated synthetic tests from `backend/` with `PYTHONPATH=. python -m pytest -q tests/test_forecast_drift_audit.py`. For operational integration, Loop 1 must provide legally entitled authenticated completed-candle provider receipts, server-owned time, source identity, session calendar, feed freshness, and a full immutable record census. Loop 5 must reconcile each forecast against the durable event journal, freeze cohort/threshold registration, add crash-safe scheduled evaluation, and independently validate alert delivery. Paper fills require separate prospective executable bid/ask and an auditable paper ledger; historical BID bars are not executable quotes. Real-money execution remains disabled pending eligible supported broker, fresh quote, risk caps, and specific owner confirmation for each order.
