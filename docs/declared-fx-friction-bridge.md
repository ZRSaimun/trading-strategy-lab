# Point-in-time CFD friction currency bridge (offline Loop 3)

`frontend/lib/declared-fx-friction-bridge.ts` calls the strict source-aware `auditDeclaredQuoteExecutions` validator before translating its declared per-fill **half-spread + signed slippage + commission** from instrument quote currency to a declared account currency. It preserves all 13 quote-currency decimal places and uses a six-decimal FX rate and BigInt multiplication to retain 19 account-currency decimal places; no intermediate floating-point rounding or double counting.

For cross-currency fills, each fill requires an exact-identity FX observation with a bounded quote age and `observedAt <= recordedAt <= filledAt`. Duplicate fill FX, orphan FX, mismatched source/currency/hash, inconsistent reuse of one FX quote ID, stale FX, post-fill records and missing observations fail closed. For native-currency fills, the only permitted conversion is exact identity with no fabricated FX feed. The declared CFD cash-per-price-point multiplier remains under the existing strict quote/fill validator.

The result reports **observed** friction for present fills and only reports **complete** friction when all declared orders are filled and each cross-currency fill has a point-in-time FX observation. No fills => null costs, not a free trade. Partial fills => no complete cost. This is a quote-side research decomposition, **not** an independent broker statement reconciliation, full round-trip cost, financing model, margin estimate, actual account balance, or verified P&L. No FX quote, broker contract specification, fill, completeness assertion or source hash is independently authenticated. Real/demo order submission remains unavailable (`mayExecuteOrder=false`).

Run synthetic tests with `cd frontend && npm test`; strict typecheck with `npm run typecheck`. Historical or demo-broker comparisons require permissioned, authenticated point-in-time quotes, contract specifications, settlement records, financing and FX evidence, frozen evaluation rules and untouched holdouts. Do not interpret passing tests as profitable performance.
