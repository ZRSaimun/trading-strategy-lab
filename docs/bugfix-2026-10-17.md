# Market and persistence bug investigation — 2026-10-17

## Reproduced against the published v0.6 UI

A public browser check at a 390×844 mobile viewport inspected actual candle rendering and provider error states, without extracting candle/quote data for analysis. This is mobile viewport testing, not a physical iPhone/Safari guarantee.

| Exact feed | Observed result before this fix |
|---|---|
| OANDA:XAUUSD | Candles rendered |
| NASDAQ:NDX | No candles; “This symbol doesn't exist” / “This symbol is only available on TradingView” |
| OANDA:XAGUSD | Candles rendered |
| NYMEX:CL1! | No candles; same provider restriction |
| NASDAQ:NVDA | Candles rendered |
| NASDAQ:TSLA | Candles rendered |
| OANDA:EURUSD | Candles rendered |
| COINBASE:BTCUSD | Candles rendered |
| COINBASE:ETHUSD | Candles rendered |
| CME_MINI:NQ1! | No candles; same provider restriction |

Market selection changed the app's symbol and provider state; no stale Gold iframe was reproduced. The iframe was not blocked in that browser. A 1H→1D interval change worked. Navigation wrapped cleanly, but the horizontal market picker is less discoverable on iPhone.

Sources inspected:
- https://zrsaimun.github.io/trading-strategy-lab/
- https://www.tradingview-widget.com/embed-widget/advanced-chart/
- https://www.tradingview.com/widget-docs/faq/data/

The provider FAQ explicitly states that a symbol can be unavailable in widgets and that buying a personal TradingView plan does not unlock website widget data. This cannot be repaired by fabricating candles or relabelling another instrument.

## Changes

- Confirmed restricted cash/futures feeds show an explicit restriction panel and exact-source link, instead of a known broken iframe.
- The user can explicitly select OANDA NAS100USD, WTICOUSD, JP225USD or SPX500USD CFD alternatives in the corresponding market. These are separately labelled proxies; there is no automatic cash/futures substitution. Selecting NQ's alternative explicitly says it is not NQ futures.
- Every displayed symbol is validated by an allowlist and the selected symbol is used in the iframe key, URL, title, source note and external link.
- Mobile uses a native market dropdown rather than relying on a horizontally hidden watchlist. Touch targets and select font sizes are improved for iPhone-size screens.
- Provider frame loading, slow-page and error messages support reload and exact-source navigation. `onLoad` is labelled only as the page opening, never as proof of candles, live data or entitlement.
- Research data requests now check both request generation and current instrument/timeframe before updating the UI. Instrument/timeframe changes immediately clear stale chart/drawing state.
- A drawing save/delete that finishes after switching instruments no longer updates the wrong chart's drawing list.
- An import finishing after an instrument switch preserves the current selection rather than jumping to the imported instrument; the upload selector is disabled while importing.
- Local mutations are serialized within a browser tab, preventing lost drawings and audit/history entries during concurrent read-modify-write operations. Failed writes do not poison later operations; duplicate retained alert events stay idempotent. Cross-tab coordination remains pending.
- A failed private-service status request displays SERVICE UNAVAILABLE rather than remaining at Checking indefinitely.

## Verification

Frontend suite: 28 tests, including real fake-IndexedDB concurrent drawing/audit persistence, recovery after a failed mutation, simultaneous alert deduplication, and every market/alternative's exact symbol configuration. Existing backend suite: 16 tests. Production builds and CI are required before release.

The initial browser check verified original feeds only. New alternative feeds require a separate post-deployment rendering check; a symbol existing on the provider website is not proof of widget entitlement. Nikkei, SPX, VOO, DXY, yields, VIX and GBPUSD were outside that initial ten-feed rendering sample. Any follow-up findings belong in a later section with their actual results. Full CSV/chart/replay/backtest/credential browser coverage and physical iPhone/Safari testing remain incomplete.

## Unchanged external requirements

Research Charts/backtests/replay alerts still need authorized data in the browser or private backend. A blocked provider display is different from missing research data. No key, paid feed, brokerage account, public private-backend endpoint or real-money execution was added.
