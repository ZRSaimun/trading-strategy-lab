# Offline as-of economic-event collision attribution census

`app.offline_event_collision.audit_declared_event_collision_asof` is a **disconnected, read-only research diagnostic** for event-window overlap. It first validates the entire caller-declared revision inventory with `audit_declared_event_asof`, using the strict `observed_utc < decision_utc` minute-level rule and source-local v2 revision-history envelope. It never fetches news, prices, quotes, or orders.

For every visible event schedule, form the inclusive interval `[scheduled - before_minutes, scheduled + after_minutes]` with bounded integer widths `0..1440`. Sort by start and event ID, then sweep all visible intervals into connected components, treating touching endpoints as overlapping. This includes **indirectly connected neighbors** and events outside the decision's own window whose intervals overlap a decision-active event. Return only components containing a decision-active event. An apparently isolated decision event is not isolated if its interval touches another event's interval even at a single minute.

`OVERLAPPING_DECLARED_WINDOWS` flags confounded single-announcement attribution in the *declared* calendar. `ISOLATED_DECLARED_WINDOW` means exactly one declared event in the relevant connected component; it **does not establish economic causation or complete calendar coverage**. `NO_DECLARED_WINDOW_AT_DECISION` is **not permission to trade**: an incomplete calendar can omit the most important release. The output permanently sets `trade_authorized=False`, `authenticated_calendar=False`, `coverage_verified=False`, `receipt_provenance_verified=False`, `single_event_attribution_verified=False`. A connected component is deliberately conservative; events connected only transitively may not directly interact with the decision. No impact ranking, units, instrument mapping, verified release receipts, or profitability is inferred.

The versioned SHA-256 checksum binds the source/cutoff/full-visible-revision-v2 envelope, window policy, direct event IDs, relevant components and status. It is a deterministic reproducibility checksum, not a vendor attestation. Inputs are not mutated; row order and future invisible revisions cannot alter the historical report. The sweep is `O(n log n)` for at most 5,000 declared revisions. Synthetic regressions cover empty, isolated, boundary-touching, transitive, disjoint, strict receipt cutoff, rescheduling, ordering, checksum and invalid policies. Run `cd backend && PYTHONPATH=. python -m pytest -q tests/test_offline_event_collision.py`.

**Activation gate:** Independently authenticate the original calendar source, first-release publication and receipt clocks, complete event coverage, exact instrument/source/session market bars, and realistic BID/ASK spreads, slippage, commission and financing. Freeze hypotheses before chronological holdout testing. This research module cannot authorize paper or real-money orders and is not wired to a production route.
