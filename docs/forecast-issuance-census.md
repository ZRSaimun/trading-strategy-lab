# Loop 5 — observed-candle forecast issuance census (disconnected)

`backend/app/forecast_issuance_census.py` audits a `ForecastEventStore.load` snapshot without writes or network calls. Given a **separately predeclared** set of model versions and 1/3/12-candle horizons, it counts forecast issuance opportunities for *each completed candle that actually appears in the journal*. It reports `issued`, `missed`, `open`, and `ineligible` by model and horizon, with at most 20 missing base timestamps per group. A full causal `_replay` is required and every derived forecast must match the snapshot; forged settled outcomes and altered events fail closed.

An observed candle is ineligible only if its receipt is already outside the allowed forecast-issuance window. An unissued candle still within the permitted window is `open`, not prematurely counted as a miss. Once the window expires, it becomes `missed`. The exclusive issuance deadline is `min(baseStart + 2*candleSeconds, baseStart + candleSeconds + maxLagSeconds + 1)` in integer epoch seconds, matching the journal's `issuedAt < nextClose` and `issuedAt - baseClose <= maxLagSeconds` rules. The final observed candle is included. A gap between observed candles is counted but **not** declared a missing market bar; market sessions are unverified.

**Important limitations:** This census cannot see candles never received or written to the journal, nor models omitted from the caller's declared population. `completeOnObservedCandles` means only that every *observed* candle has the declared issuance, and is false for an empty journal; it is not authenticated prospective coverage. Caller-supplied as-of clocks and model declarations are not independently trusted. No source entitlement, market-session completeness, forecast calibration, statistical significance, real alert delivery, executable bid/ask, paper fill, net return, maximum drawdown or profitable edge is established. Output flags explicitly prohibit interpreting it as live evidence or order authorization.
