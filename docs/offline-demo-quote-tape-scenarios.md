# Disconnected quote-tape demo fill scenarios (Loop 3)

`app.offline_demo_quote_tape_simulator` provides **offline, hypothetical, source-identity-bound order lifecycle scenarios** for one declared whole-contract MARKET or LIMIT order. It does not connect to a broker, submit demo/live orders, cancel broker orders, store credentials, place stops, compute trading returns or certify profitability. The result explicitly sets both execution permissions to `false`.

A caller supplies exact provider/venue/account/instrument identity, bid/ask quotes, quote observed/received timestamps, **declared** per-quote executable depth, quote freshness/spread limits, latency eligibility, expiry, adverse slippage, commission and optional synthetic cancel-request/effective times. It uses Decimal arithmetic to calculate scenario entry fills and decomposed entry-side spread/slippage/commission; spread is measured against the mid-price and is **not** an additional charge on top of executable fill prices. This is not a realized P&L calculation.

Conservative chronology: no fills using quotes observed before order submission; no fills before eligibility/latency; no fills on stale/crossed/out-of-order or over-spread quotes; expiry and effective cancellation win ties; cancel requests alone do not erase fills; partial fills retain exposure. A LIMIT order fills only when the adverse-slippage-adjusted executable price meets its limit. Declared depth is consumed at most once per quote, and filled quantity never exceeds the requested amount. A quote without declared depth cannot be filled. After a tape ends, unresolved orders remain explicitly unresolved rather than assuming a broker did not fill.

`fingerprint_demo_quote_tape` binds a deterministic SHA-256 receipt to the exact scope and quote tape. It **does not** independently authenticate a provider, establish quote completeness, prove a preregistered holdout, or make depth executable. There is no queue-position, market-session, gap, volatility, partial-cancel broker acknowledgment, real margin, stop/OCO, financing, settlement FX, financing revision or multi-order portfolio model. Quote depth at successive snapshots may be replenished or duplicated in reality. These scenarios must **not** be treated as a fill forecast or used for actual trading permission.

Local verification: `cd backend && PYTHONPATH=. python -m pytest -q tests/test_offline_demo_quote_tape_simulator.py`. All inputs are synthetic; multi-year net-of-cost strategy evaluation requires independently frozen chronological holdouts, licensed-source compliance, actual bid/ask quote histories, authenticated broker fills and financing, and out-of-sample evaluation. A real demo adapter needs broker-specific documented capabilities, securely scoped demo credentials, idempotent durable order state, account/stop/position reconciliation and owner-approved policy before any operational use. Trading 212 CFD order APIs must not be invented. Merge only after exact-head full CI and conflict review. Do not deploy operational features without an independently verified production backup, rollback and health checks; this disconnected module requires no production activation.
