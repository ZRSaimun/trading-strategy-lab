# Loop 5: offline forecast-review delivery journal replay (24 October 2026)

`frontend/lib/forecast-delivery-journal.ts` is a pure, disconnected, **UNVERIFIED_LOCAL_RESEARCH** state-machine validator for self-attested forecast-review events from draft PR #27. It is not a queue service, transactional database, notifier, market feed, authenticated audit trail, paper trading account, or broker connection. It makes **no** network requests and **never** submits orders or delivers messages.

The caller supplies an event array and an untrusted `asOf` timestamp. Each journal entry has a contiguous sequence number, monotonic timestamp, deterministic source/model/horizon-scoped candidate ID, and a strict lifecycle: `QUEUED -> CLAIMED -> ACK_RECORDED` or `QUEUED -> CLAIMED -> RELEASED -> CLAIMED` with a fresh attempt ID, or `QUEUED -> CANCELLED`. Unknown, duplicate, missing, reordered, backdated or future events fail closed. `ACK_RECORDED_UNVERIFIED` is only a self-reported receipt identifier, **not evidence that a notification was delivered**. An in-flight claim replays as `IN_FLIGHT_NEEDS_RECONCILIATION` after a restart; it is never silently made eligible for retry. The replay result remains `live=false`, `transportConnected=false`.

The candidate must preserve offline-only flags, exact provider/venue/source/price-side/timeframe identity, a causal completed target close, and consistent descriptive Brier metrics. The replay does not authenticate candidate creation or prove historical data was prospective. Input events can be edited or discarded; sequence continuity cannot detect a maliciously rewritten whole journal. No cryptographic provenance or independently verified provider receipt is asserted.

**Integration prerequisites:** Loop 1 must first establish an authorized completed-candle source with server-owned receipt timestamps, market-session/entitlement checks and durable forecast issuance/settlement. Then use a transactional append-only server journal with uniqueness constraints, atomic outbox claims, independent authenticated notification receipts, crash-safe retries/reconciliation, retention and integrity/audit controls. Never call a notification transport before its claim is durably committed. Do not automatically retry an ambiguous in-flight claim; reconcile provider state first. Re-test two-worker races and forced crashes in staging. No CFD broker API or live order path is authorized by this module.

Local verification: `cd frontend && node --experimental-strip-types --test tests/forecast-delivery-journal.test.ts` (8 synthetic tests), and strict TypeScript compilation. The fixtures are invented; no market data, real deliveries, actual forward accuracy, P&L, drawdown, spread, slippage or financing have been measured. The feature is deliberately not wired into the production UI or alert transport.
