# Offline demo statement population audit (Loop 3)

`auditDeclaredDemoStatementPopulation(scope, manifest, orders)` checks whether a bounded, self-declared statement ID manifest agrees with all supplied demo order lifecycle events. It invokes the existing strict single-order lifecycle validator for each order and detects reused client-order IDs, event IDs, fill IDs, and broker-order IDs **across orders**. Four ID sets are compared separately, returning sorted missing and unexpected IDs for reconciliation. Invalid sources, malformed/duplicate expected IDs, unbounded populations and invalid individual lifecycle sequences fail closed.

`DECLARED_POPULATION_MATCH_UNVERIFIED` means **only that two caller-supplied collections agree**. It is not evidence that the provider produced them, that the export contains every event, or that any fill actually occurred. `DECLARED_POPULATION_MISMATCH` exposes discrepancies. Even an empty declared event population can match an empty expected event manifest; that must never be interpreted as zero fills, zero exposure or complete broker history. Terminal and remaining quantities are declared, not authenticated. This tool does not infer monetary costs, P&L, contract multipliers, financing, or FX, and always returns `mayExecuteOrder:false`.

The input is a single source/venue/instrument/account/statement identity and the existing single-order quote batch scope. Multi-account or cross-source statements must be reviewed separately. The caller must obtain an independently authenticated **complete** supported demo-broker statement and verify its provenance, permissions, date range, ordering and provider-specific order/fill semantics before any claims about completeness. A hash string supplied by the caller is not authentication. No Trading 212 CFD API actions, network calls, broker credentials, real/demo orders, deployment changes or licensed data publication are involved.

Run `cd frontend && node --experimental-strip-types --test tests/demo-statement-population-audit.test.ts` and `npm run typecheck` with dependencies installed. This is an isolated opt-in research module; no UI or execution routing is enabled.
