# Offline demo order lifecycle reconciliation (Loop 3)

`auditDeclaredDemoOrderLifecycle(scope, intent, events)` is a **disconnected, opt-in research helper**, not a broker integration. It consumes one caller-declared demo order and its bounded event population, bound to one provider, venue, instrument, account alias, quote currency, statement SHA-256 and quote-batch SHA-256.

It models `SUBMITTED → ACKNOWLEDGED → PARTIALLY_FILLED → FILLED`, plus `CANCEL_PENDING`, `CANCELED`, `EXPIRED` and `REJECTED`. A cancellation **request** does not erase exposure: fills may arrive while cancellation is pending, and a partially filled canceled/expired order retains its executed quantity. Missing events do not imply a completed order, zero fills, zero costs or zero risk.

The audit rejects unknown fields, source mismatches, duplicate event/fill IDs, non-monotonic event/receipt clocks, future records, fills without acknowledgment, overfills, fills after terminal states, and stale/crossed/mismatched quote snapshots. It computes integer-contract weighted average fill price (six decimals, half-up) and declared commission totals (two decimals) with BigInt fixed-point arithmetic. Quote age uses event time and quote-observed time in **milliseconds**; it is not a signed quote or executable price guarantee. Event streams must be ordered by event time and receipt time; out-of-order real broker exports must be independently reconciled before review, never silently sorted here.

**Limits:** All inputs, hashes, account identifiers and event populations are self-declared. The helper does not read broker statement bytes, validate export completeness, authenticate order acknowledgments, reconcile partial fills against actual provider ledgers, infer financing, estimate P&L or certify strategy returns. It supports positive whole-number contracts only; fractional units, replacements, OCO/stop orders, market-session validation, FX conversion, margin, position netting and multi-order portfolios are deliberately outside scope. It does not place real or demo orders, store credentials, connect to Trading 212 CFDs or authorize execution. No new API endpoint, persistence or deployment configuration is enabled.

Run `cd frontend && npm test` and `npm run typecheck` after dependencies are installed; new tests can also run with `node --experimental-strip-types --test tests/demo-order-lifecycle-audit.test.ts`. Promote to a real demo adapter only after confirming documented broker API capabilities, read-only authenticated export provenance, replay-safe persistence, and independent reconciliation against actual demo records. Keep all real orders blocked pending fresh executable quotes, owner-confirmed details, explicit caps and supported account/provider credentials.
