# Day mode and provider market displays (v0.5)

## Theme

The initial interface uses a white day theme. A Day mode / Night mode switch is visible in the page header, including mobile; the sidebar has the same control on desktop. The preference is saved under `tsl-theme` in browser localStorage. A saved night preference is respected on future visits. Both terminal and research chart palettes change; no CSS inversion/filter is used. Embedded chart configuration uses the same light/dark setting. Theme changes recreate the provider chart, so temporary external chart tools may reset.

## Why the chart was empty

The existing charting library renders supplied candles; it does not include a market-data feed. No CSV had been bundled and no provider credentials had been configured. Browser IndexedDB is specific to this browser profile and origin. A separate device or cleared browser storage has no imported data.

Market Charts is now the initial page and provides a TradingView-hosted **display-only chart**. Research Charts is the existing imported-candle workspace with manual saved drawings, replay and research observations. Backtests, replay alerts and the journal do not consume the external widget data. This is not a substitute for completing the licensed ingestion pipeline.

## Provider display integration and licensing review

TradingView's official Advanced Real-Time Chart documentation permits embedding its free widget. The implementation uses the same remote `/embed-widget/advanced-chart/` iframe route and URL-encoded configuration generated by its official external-embedding loader. Attribution and provider branding remain. It does not scrape prices, extract candles, call private TradingView APIs or send data to our backtester/AI.

Sources reviewed 2026-10-17:
- https://www.tradingview.com/widget-docs/widgets/charts/advanced-chart/
- https://www.tradingview.com/widget-docs/faq/data/
- https://www.tradingview.com/widget-docs/faq/general/
- https://www.tradingview.com/policies/
- https://s3.tradingview.com/external-embedding/embed-widget-advanced-chart.js

Important limits: widget market data can be delayed, and some symbols are only available on TradingView's main site. A paid TradingView account does not automatically upgrade widget entitlements. Underlying data is display-only; non-display analysis, extraction and automated reuse are not enabled here. No new subscription or exchange entitlement was purchased. No ten-year coverage is promised. No raw historical dataset was downloaded or bundled in this change.

These are requested provider display identities, **not independently verified per-symbol widget entitlements**. Some may show a provider restriction. Cash indices, ETFs, OTC quotes, spot crypto and continuous futures are explicitly different instruments. No feed is silently replaced. Continuous futures display choices are not individual expiry contracts and remain excluded from our simulator.

The selected timeframe and quote time/data status are shown by the provider. The host app does not have access to those cross-origin values and does not invent a last-update time or declare all data real-time. The page includes reload, disable and exact-feed external-link controls if the widget is blocked or unavailable.

## Privacy

The iframe is pinned to `https://www.tradingview-widget.com` and is cross-origin. Its sandbox allows scripts and its own origin so provider resources can operate; it cannot access our origin's IndexedDB/localStorage through the browser same-origin policy. No private candles, research notes, report contents, session cookies or keys are included in its URL configuration. No third-party script runs directly in the host page.

The external chart makes requests to TradingView, which necessarily receives network metadata such as IP and selected symbol. This is explained in the UI and the provider FAQ. External chart loading can be disabled for the current view. No application analytics tracker was added. The iframe has no arbitrary shell, application API token or broker connection.

## Verification

Three tests verify distinct instrument identities, symbol/timeframe allowlisting including script-injection rejection, and a pinned remote URL containing public display configuration only. Existing research/API tests also run. The provider iframe endpoint and official loader were reachable over HTTP. Full browser rendering, individual symbol access, provider delay and candle timestamps have **not** been verified end to end. Browser QA is unavailable in this managed environment. Never equate a build/HTTP check with a verified live quote.

## Explicit feed selection usability (v0.10)

Restricted feeds expose one-click buttons for their exact, clearly labelled CFD alternatives and an immediate external link for the original instrument. No alternative is selected automatically. Once selected, each market's exact feed is retained across market switches and refreshes under `tsl-display-feed-choices`. Only allowlisted symbols belonging to that market can be restored; null, malformed JSON, unknown symbols and cross-market substitutions are ignored. If localStorage is unavailable the selection lasts for the current component session. Backup files do not include these display preferences.

Native feed options now show concise exact symbols, with the CFD identity and full source note immediately below. Known restricted primary entries say “choose feed” on mobile and “external only” in the desktop source label. Selecting a new market re-enables the external chart after it was disabled on another market. A chart frame's load event still does not prove candle availability.
