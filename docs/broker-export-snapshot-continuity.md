# Offline broker-export snapshot continuity (research only)

`backend/app/broker_export_snapshot_continuity.py` compares **two caller-declared normalized export snapshots** from the same provider, venue, account alias and settlement currency. It is an additive, disconnected read-only research audit; it does not parse broker-native formats, authenticate statements, call a provider, submit demo/live orders or establish profitability. **Do not infer that Trading 212 offers a CFD order API.**

A snapshot explicitly declares a source identity, unique snapshot ID, SHA-256 of alleged statement bytes, inclusive UTC coverage window, export and ingestion times, and up to 5,000 events. Every event has a unique ID, type (FILL, COMMISSION, FINANCING, ADJUSTMENT), instrument, position, event and recording times, exact decimal quantity/cash, revision, optional predecessor and evidence digest. All fields use strict bounded schemas; cash-only events must have zero quantity, while fills must have a side, positive quantity and zero cash. Amounts for cash events use **positive = charge/debit**, negative = credit, with no FX conversion. Corrections are appended with increasing revision/recording time and one predecessor per correction; previous rows remain immutable. This is a **normalization contract for research**, not a broker statement schema or proof of correct broker accounting.

The audit rejects source drift, truncated coverage, altered or missing old events, duplicate IDs, correction forks, invalid clocks, revisions and historical backfills that were allegedly recorded before the earlier export but omitted from it. A **legitimately late-recorded historical charge or correction** is retained and yields `WITHHELD_LATE_HISTORICAL_POSTINGS`, not a falsely complete earlier statement. It reports separate exact-decimal effective commission, financing and adjustment totals for each snapshot, excluding superseded versions. These are declared cash components, **not net P&L**; fills are not valued, and no spread, slippage, CFD rollover calendar or trading return is inferred. Event ordering does not affect the declaration digests.

## Validation and limitations

Run `cd backend && PYTHONPATH=. python -m pytest -q tests/test_broker_export_snapshot_continuity.py`. The synthetic suite includes malformed and adversarial inputs, appended corrections, retroactive omissions, exact cash and a 2018–2026 simulated event population. **No real multi-year archive or broker data is loaded**. Statement SHA-256 strings, event clocks and completeness are all caller-controlled. Even a clean audit cannot prove a broker actually issued the export, that omitted events never existed, that quoted prices were executable, or that financing is correct. Authenticated read-only broker export retrieval, independent custody of both raw byte streams, explicit provider-native schema mapping, cash-ledger reconciliation and frozen holdout evaluation are mandatory before using any result for a trading decision.

This module has no API route or execution interface. Real-money orders remain disabled and require separate, explicit owner confirmation for each order, supported provider/account, fresh executable quotes, secure credentials and risk caps.
