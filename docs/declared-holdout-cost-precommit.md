# Outcome-free row-cost scenario precommitment (offline)

`backend/app/declared_holdout_cost_precommit.py` provides a **pre-outcome** deterministic SHA-256 commitment for the exact caller-declared row-cost scenario set. Call `prepare_declared_holdout_row_cost_scenario_set_sha256(manifest, census, scenarios)` **before supplying outcome receipts**. It validates the declared manifest and complete holdout census, each scenario ID, every source/row identity and each nonnegative exact-decimal cash debit, then canonically sorts scenario IDs and observation IDs. The digest uses the same `declared-holdout-row-cost-scenario-set-v1` structure as the post-release `audit_declared_holdout_row_cost_stress` report.

An external, immutable, independently trusted record must preserve the digest and timestamp **before** the holdout is exposed. `require_declared_holdout_row_cost_scenario_set_sha256(manifest, census, scenarios, expected_sha256)` rejects malformed or mismatched expected digests; the caller must retrieve the expected digest from that trusted record, not compute it from the same mutable inputs at evaluation time. The helper does **not** verify the external record, enforce single-use holdout access or protect against repeated experiments. A caller can trivially invent or backdate its own expected digest.

This path accepts no outcomes, broker quotes or credentials; it makes no network calls, places no orders and cannot prove source authenticity, timestamp convention, broker-executable spreads/slippage, CFD financing, FX conversion, margin or profitability. Its digest is available for fewer than 30 observations, but the existing release audit continues to withhold outcome-derived metrics for such populations. Do not treat the digest, a declared registration clock or a green synthetic test as proof of untouched chronological holdouts or trading edge.
