# Offline prospective forecast cohort coverage (Loop 5)

`frontend/lib/forward-cohort-coverage.ts` audits a **predeclared** inclusive UTC-aligned series of non-overlapping 1-, 3-, or 12-candle forecast issue slots, using the same exact feed identity and model version. It detects absent issued records, gap-voided outcomes, overdue pending forecasts, immature forecasts and late settlements separately. It reports timely settlement coverage **over all matured expected slots**, not just the successfully scored subset. A selective subset of winners therefore cannot silently become a complete forward accuracy sample.

The `expectedStart`/`expectedEnd` bounds are caller-declared, not independently timestamped or registered; absence outside the chosen interval cannot be discovered. An omitted issued record inside the interval is treated as missing, not as an incorrect prediction. A `COMPLETE_DESCRIPTIVE` result means the supplied cohort is internally complete and timely **only**; it does not prove forecast skill, trustworthy market observations, continuous monitoring or reliable notification delivery. No statistical significance, profit, max drawdown or executable prices are computed. Results always set `live=false`, `authenticated=false`, `persisted=false`, `alertsEnabled=false`, and `execution=NONE`.

Run synthetic regression tests with `cd frontend && node --experimental-strip-types --test tests/forward-cohort-coverage.test.ts`; strict TypeScript compile must include the existing `forward-forecast-ledger.ts` contract. Tests do not use real historical or prospective data.

**Integration prerequisites:** Loop 1 must provide an authorized authenticated completed-candle feed, server-owned UTC receipt times, session/expiry-aware observation rules and a transactional append-only issuance/settlement journal. Store and independently timestamp the intended cohort schedule **before** any outcomes. Check multiworker concurrency, restart replay, immutable records and delivery receipts. Do not infer executable quotes from BID-only archives or use this offline coverage report to enable alerts, paper fills or live orders.

**Release gate:** Keep PR #27 draft. Reconcile branch with current main and re-run all CI; production merge/deploy requires independently verified backup restoration, rollback and health. No money, credentials, broker calls, subscriptions or production datasets are touched.
