# Revision-aware point-in-time feature vintage audit (offline)

`backend/app/asof_feature_vintage_audit.py` implements an **offline, self-declared metadata-only** as-of join for research features. Each decision has a UTC second clock and source identity; each required feature series has its own provider, venue, instrument, declared archive SHA-256 and maximum observation age. Feature vintages have observation time, publication/availability time, consecutive revision number and a value SHA-256. Raw values are **not** accepted or emitted.

For each decision and required series, select the latest *observed* record **published by the decision time**, then the latest published revision of that observation. A later observation unavailable at the decision cannot displace an older available observation. A later revision to an older observation cannot displace a newer available observation. Missing or stale series withhold complete coverage, never imply a zero value. Published-at-decision and exactly-max-age boundaries are inclusive. Revisions must begin at zero and have strictly increasing publication times; incomplete declared revision chains are rejected.

The deterministic SHA-256 receipt covers all supplied metadata, including future vintages, independent of input ordering. This is a **consistency checksum, not source authentication, independent preregistration, proof of historical availability or evidence that all revisions were exported**. The as-of selections never expose a later-known value hash at an earlier decision. The report never estimates returns, backtest performance or trading safety. It does not claim that an observation was legally accessible, correctly timestamped, complete or actually published when declared. A retroactively created or modified dataset can still fabricate an internally consistent historical view.

The API accepts no broker credentials, orders, economic actuals, forecasts, trade fills, or live market calls. It performs no network or database writes. Its `may_execute_order` and `verified_profitability` flags are always false. No licensed archive is included.

Run synthetic tests from `backend`: `PYTHONPATH=. pytest -q tests/test_asof_feature_vintage_audit.py`. For any genuine historical strategy test, verify provider release logs, archived vintages and source rights independently, lock the source and protocol before evaluation, then reconcile realistic executable costs, financing, risk, and untouched holdouts. Do not infer Trading 212 CFD API support.
