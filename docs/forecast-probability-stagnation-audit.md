# Declared forecast probability stagnation audit (Loop 5)

`app.forecast_probability_stagnation_audit.audit_forecast_probability_stagnation` is a **disconnected, read-only operator diagnostic** for a `ForecastEventStore.load`-compatible snapshot and separately declared expected `(modelVersion, horizon, baseStart)` schedule plus explicit abstentions. It does not authenticate data, issue predictions, contact recipients, simulate fills or trade.

The audit first requires the strict forecast-or-abstention census from `audit_forecast_decision_coverage` to match exactly. Missing, unexpected, duplicate or contradictory decisions withhold all statistics. Each model version and 1/3/12-candle horizon is evaluated separately. By default at least 30 declared decisions and 30 actual forecast rows are required. It counts exact distinct probability values, the most common exact probability, its share, the longest run of an identical probability on *adjacent expected candle starts*, and the trailing run. Abstentions and calendar gaps break runs. Operator review is flagged when a run reaches 12 candles or an exact value accounts for at least 90% of forecast rows. Thresholds are **descriptive heuristics**, not calibrated false-alarm rates or statistical significance tests.

A constant probability can be the correct output of a deliberately frozen climatology or a coarse/quantized model. Conversely a model can be broken while its output varies. Binary floating-point exact equality does not group near-equal values. These checks should prompt review, never automatic retraining, deletion, notification or trading. The declared schedule can omit expected candles; external, independently witnessed model schedules and session calendars are still required to establish completeness. All returned authentication, delivery and execution permissions are `false`.

Synthetic regression tests: `cd backend && PYTHONPATH=. pytest -q tests/test_forecast_probability_stagnation_audit.py`. No provider, broker, secret, database, network or production dataset is accessed.

**Loop 1 handoff:** supply independently entitled prospective completed-candle receipts, server-owned UTC receipt clocks, verified provider/price-side and session calendars, and independently registered immutable decision schedules. A matching caller-declared census is not independent proof of a functioning live feed. Production activation also requires backup restore, rollback rehearsal, authenticated health and recipient opt-in.
