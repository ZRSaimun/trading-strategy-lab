# Loop 5 — causal, disconnected forecast issuance integration

`backend/app/forecast_causal_issuer.py` composes the existing transactional `ForecastEventStore` with a deliberately simple, deterministic **Jeffreys-smoothed empirical up-frequency baseline**. It has **no FastAPI route, scheduler, live provider, alert transport, paper fill, broker connection or order execution**. All outputs are explicitly `UNAUTHENTICATED_DISCONNECTED_RESEARCH`, `live=false`. It is **not enabled in production**.

## Method and timing

For each accepted, newly observed *completed* source-identical candle, estimate `P(close[t+h] > close[t])` for h = 1, 3 and 12 bars using only prior fully observed target closes. For h bars, training bases must align to a fixed UTC bar-index phase (`floor(start/seconds) % h == 0`), be h bars apart, and have **every intervening completed candle** observed. Gaps and closures are never bridged. With `n >= min_samples` (default 30), probability is `(up_count + 0.5)/(n + 1)`; otherwise that horizon abstains. This is a descriptive, uncalibrated baseline, not a calibrated probability or independently established trading edge. Prices must be positive and finite. `ForecastEventStore` stamps receipts and refuses stale/retroactive issues. The issuer never backdates issuance.

The journal's existing optimistic compare-and-swap persists each candle and each horizon's forecast separately, with a per-event audit row. A crash can leave a completed candle with fewer than three forecasts. Retrying **the exact same** candle within the issuance window fills only missing horizons with deterministic IDs; late recovery fails closed rather than manufacturing an earlier forecast. Concurrent CAS conflicts raise and require operator reconciliation. An uninterrupted cycle is **not** a single transaction across all horizons. Fixed-phase nonoverlapping training outcomes reduce label overlap but do not remove serial dependence, market-regime drift, provider errors, costs or selection bias. The minimum sample policy is embedded in the immutable model version to prevent silent model changes on restart. A fixed minimum sample is not a confidence guarantee.

## Verification and activation gates

Run `cd backend && PYTHONPATH=. pytest -q tests/test_forecast_causal_issuer.py`. The synthetic SQLite tests cover fixed-phase outcomes, gaps, insufficient history, 1/3/12 horizons, idempotent restart, partial-crash recovery, stale backdating and identity rejection. These do **not** establish prospective accuracy, trading profitability, net returns, downside drawdown, live quote freshness or broker suitability.

**Do not connect an unauthenticated caller or historical BID archive to this journal.** Loop 1 must first supply an entitled provider adapter with authenticated source identity, verified completed-bar/session policy, trusted server-owned receipt time and independently verifiable receipts. An operational scheduler needs idempotent multi-process ownership, failure reconciliation, PostgreSQL acceptance, backup/rollback rehearsal and durable alert transport with actual delivery receipts. Future paper P&L needs genuine provider bid/ask observations and spread, slippage, commissions, financing and drawdown accounting; no historical BID candle is an executable broker quote. No real-money order may be sent without a verified eligible broker account, fresh executable quote, risk limits and explicit owner approval for that individual order. Keep PR draft and deployment off until exact-head CI, branch reconciliation and release gates are complete.
