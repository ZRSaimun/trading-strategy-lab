# Completed-candle receipt and observed gap audit (Loop 1)

The private Twelve Data **manual historical import** records a bounded, read-only `quality` object alongside its existing provider-specific manifest. The source remains `XAUUSD-TD` / `XAU/USD` at 1-minute UTC resolution. The audit never changes, synthesizes, interpolates or submits a candle and never calls a vendor itself.

`request_started_at` and `response_received_at` are server UTC epoch seconds surrounding the HTTP response; `request_elapsed_ms` is measured with a server monotonic clock and does not certify vendor transmission latency. The legacy `retrieved_at` field remains the request-start timestamp for compatibility. `receipt_clock=server_wall_utc` and `elapsed_clock=server_monotonic` identify these different clock semantics; neither is a provider-signed timestamp. `observed_at_utc` is the backend's response-receipt/evaluation time, not a provider-signed quote timestamp. `last_candle_close_utc` is the last accepted candle's UTC minute-end. `seconds_since_last_candle_close` is a descriptive historical age; **it does not classify the source as live or stale relative to a market session**, because no authorized market calendar or feed-delivery SLA has been verified. `observed_timestamp_gaps` counts jumps larger than one minute. `unobserved_minutes_between_candles` and bounded `gap_samples` describe those jumps; weekend/session closures and outages are indistinguishable without a verified trading calendar.

`market_calendar_checked`, `source_authenticity_verified`, `provider_entitlement_verified`, `executable_bid_ask_verified`, `live` and `may_execute_order` remain `false`. A SHA-256 of the vetted source-field snapshot is not a signed vendor statement. Historical BID/mid OHLC bars are not an executable two-sided CFD quote or broker spread.

The audit fails closed on malformed, non-UTC-minute, duplicate, out-of-order, incomplete or future timestamps. It also rejects nonnumeric, NaN, infinite or internally inconsistent OHLC values, and invalid optional volume. `ohlc_invariants_checked=true` means only that numeric bar invariants were checked; it does **not** prove a vendor source, correct venue, price side or executable quote. `price_side=UNVERIFIED` remains explicit. It uses only the already normalized completed-candle rows and a server-owned timestamp; no provider credentials are read by the auditor. Existing `gaps` and manifest fields remain unchanged for backwards compatibility. No database migration or new route is introduced.


## Provider-rights provenance: assertion is not entitlement

The import request's `rights_confirmed=true` remains a **legacy owner checkbox** for backwards compatibility. It is **not** proof of an authenticated Twelve Data subscription, symbol entitlement, or legal permission to store, display, redistribute or use data for non-display analysis. The import manifest and provider-status response now explicitly record `rights_confirmation_scope=owner_assertion_only` and `provider_instrument_entitlement_verified=false`, `retention_rights_verified=false`, `display_rights_verified=false`, `non_display_rights_verified=false`. The persisted dataset source label now says `historical API (rights unverified)` rather than falsely asserting an `authorized historical API`. These flags are deliberately never promoted by merely configuring an API key or ticking the owner checkbox. No entitlement verification endpoint, vendor call, broker connection or new credential is introduced.

Before enabling real data display or automated feed polling, verify the actual provider account, XAU/USD entitlement, instrument venue/price-side semantics, retention and display/non-display rights, and delivery latency with the provider. See [Twelve Data usage guidance](https://support.twelvedata.com/en/articles/5332349-commercial-and-personal-usage). Existing archives are not retroactively reclassified or rewritten; their manifests retain their historical provenance and should be interpreted conservatively.

## Raw vendor JSON ambiguity gate

Before constructing a normalized candle set or content-addressed snapshot, the existing bounded Twelve Data HTTP response parser now rejects duplicate object keys at **every JSON nesting level** and nonstandard NaN/Infinity numeric constants. Python's default JSON parser would otherwise silently accept the last duplicate value, so an ambiguous original provider response could become a clean-looking reconstructed archive even when the later snapshot-to-row verifier passes. Failures use the existing sanitized provider 502 path, without leaking response bodies or API credentials. The raw vendor response is **not** persisted; the existing archive is still a vetted source-field reconstruction, not an authenticated original payload. This change adds no request, feed, price, broker connection, or subscription. Offline `httpx.MockTransport` regressions cover top-level, metadata and candle-field duplicates, nonstandard constants and a valid control. Run `cd backend && PYTHONPATH=. pytest -q tests/test_provider_raw_json.py`.

## Source-snapshot-to-row reconciliation before replacement

The importer now verifies that its bounded, source-field JSON snapshot describes **exactly the normalized completed candles** being committed: the fixed Twelve Data XAU/USD UTC/1min metadata, count, each minute timestamp, OHLC value and volume-free semantics. A valid SHA-256 filename alone would not catch a bug where the archived source evidence and database rows disagree. A mismatch returns HTTP 502 **before creating a new archive or touching database rows, manifest or audit**. The snapshot parser also rejects duplicate JSON object keys at any depth and nonstandard NaN/Infinity constants, rather than silently trusting a last-key-wins interpretation of ambiguous source evidence. This is an internal consistency check; it does not authenticate the vendor, certify source licensing, validate bid/ask or prove exchange delivery time. Synthetic unit and mocked API regressions cover metadata, price, timestamp and count mismatches, including preservation of an existing imported series.

## Immutable archive verification before replacement

Before replacing the existing provider series, the importer now reopens its content-addressed historical snapshot using a no-symlink file descriptor and verifies the **complete stored bytes** against the newly vetted snapshot. A pre-existing corrupted, truncated, swapped, or symlinked archive causes HTTP 503 without changing candles, the dataset manifest or audit history. This is local storage integrity checking, **not** vendor authentication or permission to retain the data. The archive directory still requires private filesystem permissions, durable storage and a tested recovery procedure; this check does not establish any production backup or rollback readiness. Regression cases use mocked responses only.

## Atomic source snapshot publication (offline safety)

The historical importer now writes a new content-addressed source snapshot to a private, uniquely named temporary file in the same archive directory, flushes and fsyncs the file, then atomically publishes it using a no-overwrite hard link. It fsyncs the directory after publication and checks the published bytes before any candle replacement. Other readers therefore cannot see a **partially written final digest filename** after a process interruption. Concurrent writers for the same digest may race to publish, but neither overwrites the other: the losing writer verifies the winner's bytes. Existing corrupt, symlinked or nonregular targets (including FIFOs) fail closed. A symlinked archive directory is rejected. Newly created temporary files are removed on the normal success/error paths.

The directory must reside on a filesystem supporting same-directory hard links and fsync. Storage failures return the existing sanitized HTTP 503 and preserve database rows, manifest and audit. An interrupted process may leave a private temporary file for operator inspection/cleanup; it must not be treated as a valid snapshot. **This is not a verified backup, restore drill, source signature, license grant, multi-process import lock or crash-proof guarantee on an unverified filesystem.** The code does not delete or repair a corrupt published archive or modify production data. Run `cd backend && PYTHONPATH=. pytest -q tests/test_archive_store.py tests/test_provider.py` for offline regressions, including concurrent writers and publication failure.

## Tests and operational limits

Run `cd backend && PYTHONPATH=. pytest -q tests/test_completed_candle_quality.py tests/test_provider_snapshot.py tests/test_provider.py`. Tests use synthetic timestamps and a mocked provider. Real feed access, provider entitlement, quote authenticity, expected trading hours, account-level licensing, delays, actual spread and order execution **are not verified**.

Before a future authenticated completed-candle feed can be advertised as current, obtain the exact authorized provider/venue/instrument, exchange or broker timestamp semantics, feed-delay/closure calendar, contractual display/non-display rights, server receipt clock and monotonic append-only provenance. Preserve raw response evidence only when licensing and security permit. Never infer CFD API availability from an equity API.
