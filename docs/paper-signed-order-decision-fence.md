# Loop 4 — signed, order-specific human decision evidence (offline)

`backend/app/paper_signed_order_decision_fence.py` validates a **single Ed25519-signed decision envelope** against independently supplied expected review, policy, inventory, account, client-order and quote identifiers. It is an isolated, read-only proof-of-key-possession preflight, **not an owner-authentication service or permission to execute**.

The signer signs the canonical JSON returned by `signing_message(decision)` (all envelope fields except `signature_hex`; ASCII JSON, sorted keys, compact separators). The signature is 64 bytes of lowercase hex, and the externally pinned Ed25519 public key is 32 bytes of lowercase hex. No key generation, signing service, credential storage, broker API call, paper order or real-money order is implemented. Never put private keys in GitHub, API requests, logs or review artifacts.

`evaluate_signed_order_decision(decision, *, expected, trusted_public_key_hex, now_ms, used_nonces, kill_switch_active, reconciliation_healthy)` enforces exact schema and signed account/order/quote/review/risk-policy/inventory identity, APPROVE versus REJECT, review and decision expiry, fresh executable quote observation (3 seconds), transport lag (1 second), no future timestamps, declared unused nonce, inactive kill switch and healthy reconciliation. It rejects malformed and unbounded evidence. SHA-256 output is only a diagnostic fingerprint; no signature or public key material is returned.

**Security boundary:** The caller must source `expected`, the public-key pin, server time, used-nonce population and kill-switch state from independently authenticated, durable, server-side records. Passing caller-provided values is NOT verification. An Ed25519 signature proves only possession of the signing key, not human presence, uncompromised owner consent or broker order acceptance. The module does not persist or atomically consume a nonce, authenticate a review packet, verify broker inventory, or issue a one-time execution capability. Reused nonces are rejected only if present in the supplied used-nonce snapshot. Even when all structural checks pass, status is `HOLD_RECONCILIATION` and both execution flags are always `false`.

Before any live adapter: independently recompute the immutable `live_order_review` digest from the exact current broker-authenticated quote, account, inventory, contract spec and risk policy; verify key ownership with an authenticated user ceremony and managed key lifecycle; persist the signed decision in an append-only audit log; atomically reserve and consume a globally unique nonce and client-order ID; re-evaluate circuit breakers, margin, risk and quote freshness at submission; reconcile ambiguous broker responses without retrying non-idempotent orders. Obtain positive human confirmation for **each specific order**. Do not treat a signature alone as execution authorization.

Trading 212's documented public API supports Invest and Stocks ISA accounts, not CFD order execution: https://docs.trading212.com/api/section/general-information/api-limitations . Stops can gap or slip beyond modeled losses. This feature does not predict returns or guarantee profit.

Run synthetic tests from `backend`: `PYTHONPATH=. python -m pytest -q tests/test_paper_signed_order_decision_fence.py`. No production data or real credentials are required. Production release remains gated by verified backup restoration, rollback and health checks.
