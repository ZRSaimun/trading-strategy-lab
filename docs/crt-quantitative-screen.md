# 4H CRT / 15m closed-bar research screen (candidate protocol v1)

**Scope:** read-only, authenticated archive research. This branch introduces no orders, broker connections, cloud mutations, real-time signals, automated trading, or claimed market edge. This protocol is a pre-registration of **candidate thresholds** for subsequent independent holdout testing, not a backtest of their profitability.

## One source and strictly observed bars

The `CRT / ICT Research` terminal tab reads up to the most recent **2,000 aggregated bars per timeframe** from one READY, SHA-256-identified, BID-only historical ZIP archive. It checks the same dataset ID, provider, instrument, archive SHA-256 and BID-only source metadata for 4H, 15m and UTC daily reads; it never joins different instruments, providers, price sides or archive versions. The read-only engine accepts ordered, positive finite OHLC; 4H and 15m bars must be UTC-bucket-aligned with exactly 240 and 15 observed minutes respectively. It will not synthesize missing bars. Daily aggregates may include shortened sessions, outages and archive edges. Daily trend uses only **elapsed UTC daily buckets with all 1,440 underlying minutes observed**; a past partial bucket is excluded rather than treated as a valid daily close. This deliberately excludes genuine shortened trading sessions until an instrument-specific exchange calendar can establish their expected minutes. Daily validation also rejects negative or non-integer UTC timestamps, fractional observed-minute counts, and nonfinite/negative declared volume; null volume remains allowed because the daily trend uses prices only. These malformed metadata fields must not be laundered into a completed-day trend PASS. The trend is a proxy, not an ICT order block.

**Archive-boundary quality regression (24 October 2026):** A source archive may begin or end partway through a UTC 4H or 15m bucket. The API correctly reports the actual observed-minute count for these partial aggregates. The CRT tab now excludes at most the first and last incomplete 4H/15m buckets, reports how many were excluded, and validates all retained bars. An incomplete **internal** aggregate, malformed boundary price, duplicate/misaligned timestamp or invalid volume **fails closed** rather than being silently skipped. This avoids both falsely rejecting an otherwise usable imported archive and fabricating completion for missing observations. Synthetic tests cover all three cases; real-data acceptance remains pending.

**Cross-timeframe consistency audit (24 October 2026):** Before showing any CRT candidates, the UI now verifies every fully overlapped completed 4H candle against the **16 exact, consecutive 15m candles** that comprise it. The aggregate 4H open must match the first 15m open, high/low the 15m extrema, and close the final 15m close (allowing only negligible floating-point serialization noise). An interior 15m gap or a 4H/15m OHLC discrepancy rejects the screen, even when archive SHA, provider and instrument metadata match. When both the 4H candle and all sixteen constituent 15m candles report numeric volume, their totals must also agree (allowing only bounded floating-point summation error); a discrepancy fails closed. Null/missing volume cannot be substituted with zero and does **not** become verified volume merely because the price-only OHLC audit succeeds. This is an internal aggregate consistency check, **not** external volume-source authentication. A 4H candle outside the shared 15m coverage is **uncheckable**, not falsely certified; the UI reports verified and uncheckable counts. A screen with zero verified 4H bars refuses to run. This detects aggregation bugs and cross-response cache skew, but does **not** independently authenticate a broker's underlying prices or validate every underlying M1 tick. Seven synthetic regression tests cover coherent windows, OHLC mismatches, missing 15m bars, incomplete boundaries, future edits and malformed inputs.

**4H zone revision provenance (24 October 2026):** Optional pre-observed 4H supply/demand zone references must now match the **exact archive SHA-256** as well as the dataset ID and BID price side. A dataset identifier can outlive a replacement or refreshed import; matching only the ID could allow an old-zone observation to confirm a candidate on new prices. Reference timestamps must be safe integers aligned to the 4H UTC bucket, and observation timestamps must be integer seconds after the reference candle closes and **no later than the sweep candle opening**. The zone's 4H reference timestamp must also match a fully observed candle actually present in the validated 4H research window; an aligned but absent reference is `INSUFFICIENT_DATA`, not evidence. The zone must contain the sweep candle's own completed close, not the later 15m confirmation price; finite positive zone bounds are mandatory. Zones first observed during the sweep or referencing the sweep itself cannot be retroactively treated as prior context. Stale SHA, ASK-side, misaligned and fractional-time fixtures are rejected as `INSUFFICIENT_DATA`. This is defensive research metadata checking, **not** proof that a manually supplied zone is a real order block or that its observation timestamp is independently authenticated. The current UI does not ingest externally certified zone records.

**Zone-age freshness correction (25 October 2026):** The earlier 30-day check compared a zone's observation timestamp to its reference candle, so a zone recorded promptly years ago could still qualify for a current sweep. The reference 4H candle must now start **strictly less than 30 calendar days before the sweep opening**, in addition to being recorded before that opening. Stale zones are `INSUFFICIENT_DATA`, even if their price rectangle overlaps the sweep close. This conservative bound is a research assumption, not a verified institutional zone lifetime or invalidation model. Two synthetic regressions cover a stale, promptly recorded zone and a recent qualifying zone.

**Stale-certification regression (25 October 2026):** A prior cross-timeframe report can become stale if its 4H or 15m candle arrays change, or a forged list can replace a verified timestamp with an existing but uncheckable 4H timestamp without changing the counts. The certification helper now re-audits the exact current 4H and 15m OHLC inputs and requires the ordered verified timestamp list and counts to match the supplied report. Changed prices, coverage or a substituted unverified reference fail closed. Two synthetic regressions cover post-audit price edits and count-preserving timestamp substitution. This guards the integrity of in-memory certification, not the authenticity of the upstream broker/archive.

**Verified-candidate restriction (24 October 2026):** A 4H bucket can be outside the 15m window yet still look like a plausible reference or sweep. Earlier versions reported it as *uncheckable* but inadvertently allowed it into the CRT candidate engine if a different 4H bucket had passed the audit. The screen now passes **only individually certified 4H bucket timestamps** into the sweep engine. A CRT setup therefore needs two adjacent, separately reconciled 4H bars; a partially observed edge reference/sweep cannot produce a candidate or contaminate pattern counts. The cross-timeframe audit emits exact certified bucket starts, and a fail-closed selection helper rejects stale or inconsistent certification reports. Regression tests cover a synthetic false sweep formed solely by an uncheckable older 4H reference and a tampered certification report. This intentionally reduces candidate coverage; it does not reconstruct missing 15m data or prove underlying source truth.

The UI's 15m window is usually much shorter than the 4H and daily windows, so earlier 4H sweeps may be omitted from the screen. The 2,000-bar per-frame cap is **not** a multi-year or independent holdout study; a later implementation must paginate a common bounded calendar interval and report its exact coverage and source lineage.

## Fixed hypotheses (v1)

1. Two adjacent **completed 4H** bars: Candle 2 sweeps below Candle 1 low and closes back strictly inside Candle 1 range for bullish; vice versa for bearish. An ambiguous double-sided outside bar is excluded. Proposed sweep-depth fraction is outside-wick excursion / **Candle 1 full high–low range**, with a candidate **maximum 0.40**. This is a configurable *research rejection* rule, not an established profitable threshold; test alternatives with pre-declared multiple-testing correction.
2. After Candle 2 has **closed**, inspect the next 4H block of **completed 15m** candles. The first close beyond the highs (bullish) or lows (bearish) of the immediately preceding three 15m candles, with directional body, is a deterministic **local structure-break proxy**, not a formal validated MSS/CHOCH. Require a contiguous prior 20-bar 15m window. Compare that first signal candle's high–low range with the **median** of those preceding 20 ranges; proposed candidate is **>=1.5×**. Do not select a later better shift if the first fails. If the prior 20-bar **median range is zero**, the multiplicative displacement ratio is not meaningful: report `INSUFFICIENT_DATA` (while preserving the separately observed structure-shift result), never `PASS` just because the threshold evaluates to zero. Flat/unchanging quotes are not evidence of exceptional displacement.
3. **Daily context:** average of the last five *fully observed* UTC daily closes > average of the last 20 for bullish, reverse for bearish. A clock-closed day with fewer than 1,440 observed source minutes is **not** fully observed; if fewer than 20 qualifying historical daily buckets remain, context is `INSUFFICIENT_DATA`. Scheduled closures/early closes are not inferred without a verified instrument calendar. This is a deliberately simple *trend proxy*, not a validated higher-timeframe institutional order block.
4. **Volume:** only classified, independently verified actual exchange/tick history with all prior 20 positive observations may pass; compare current completed 15m volume to **>1.5× the preceding 20 mean**. The current historical ZIP API explicitly identifies its volume as `unverified_histdata`, so the UI always shows **INSUFFICIENT_DATA** for volume. Zero placeholders never count as genuine observed volume. Passing test fixtures do not establish real market volume.
5. **4H zone:** an optional, source-linked, earlier-observed supply/demand rectangle can match the candidate price, but cannot independently establish a genuine order block. No such zones are auto-created by this UI, so it shows **INSUFFICIENT_DATA**.
6. **Economic news:** always **INSUFFICIENT_DATA** until an authorized, timestamped, revision-aware release calendar and source-specific instrument/session mapping are supplied. A 15-minute pre-news block is not active. There is no trade authorization under any gate combination.

**Out of scope:** the owner's 1H FVG midpoint wick-rejection threshold, broker BID/ASK spread/funding, 1m/5m/15m CFD cost comparison, source-verified macro/VIX/CPI/FOMC, proper 4H order-block reconstruction, exchange holiday/early-close calendars, margin, live trading, position sizing and out-of-sample performance. See `docs/ny-close-cfd-research.md` and `docs/next-priorities.md`.

## Observed negative versus missing confirmation evidence (24 October 2026)

A complete CRT sweep does **not** imply that the next 4H block produced a 15m structure break. The screen now makes this distinction reproducibly:

- `PASS`: the **first** qualifying closed 15m structure-break candle is found after the manipulation 4H candle closes, with all 20 immediately preceding contiguous 15m candles observed. A PASS may be reported at that confirmation close; later 15m bars are not required and cannot retroactively change it.
- `FAIL`: **all sixteen** 15m candles in the next 4H block and each required 20-bar preceding window are complete and contiguous, but **none** has a qualifying directional shift. This is a genuine observed negative rather than an unknown outcome.
- `INSUFFICIENT_DATA`: the first eligible 15m candle, a preceding 20-bar window, or any needed subsequent 15m candle is absent or noncontiguous before a confirmed shift. The engine does not skip missing earlier evidence to select a more attractive later shift. A truncated archive tail is not counted as a negative.

When no shift occurs, displacement and verified-volume confirmation remain unavailable rather than being assigned a fictitious rejection or pass. Five additional synthetic regressions cover fully observed negative windows, a missing earlier history bar followed by a seemingly attractive shift, interior gaps, truncated tails and prefix stability. These are research evidence-status corrections, not observed profitability.

## Interpretation, limitations and next evidence

The screen counts *pattern candidates* and gate statuses, **not trades or returns**. It must not be interpreted as win rate, Sharpe, profitability, backtested execution, or a 3–6% improvement. In particular, the optional historical source may represent a CFD that trades different hours from a cash index. Historical minute data cannot establish actual executable ask prices, spread spikes, slippage, financing, news availability or broker session cutoffs.

Regression tests cover exact 4H wick fraction, first completed 15m shift, contiguous prior 20-bar displacement median, daily lookahead exclusion, volume provenance, source isolation, future-bar edits, zone timing and malformed candles. GitHub CI is the authoritative build/test result for this branch.

**Next independent study:** lock a source/instrument/session specification and fixed thresholds before untouched, purged chronological holdouts; add cost-stress negative controls and alternative 1H/4H versus short-frame CFD variants. Use actual observed bid/ask and broker contract metadata for executable estimates. Keep all execution disabled.

## Partial historical daily-bar guard (24 October 2026)

A UTC daily bar can be chronologically closed yet contain only 600, 1,000 or another number of observed source minutes. The previous trend proxy used these bars as if they were full daily sessions, potentially reversing a 5/20 close-average signal using an incomplete day. The engine requires `observed_minutes===1440` **and** daily close time no later than the 4H sweep decision timestamp; only then can that day enter the 5/20 lookback. **Further fail-closed guard (25 October):** if a known elapsed partial day occurs between the oldest selected complete daily close and the sweep, the entire trend gate is `INSUFFICIENT_DATA`, even when twenty older complete days remain. Skipping a missing/shortened day and backfilling with older closes could otherwise produce a misleading `PASS`. An incomplete current UTC day whose close is in the future is excluded, not treated as a historical gap. Synthetic regressions cover recent and interior partial days and a partial day outside the selected window. This conservative rule is not a universal CFD trading calendar: genuine early closes may be excluded and no session-adjusted daily trend is claimed.
