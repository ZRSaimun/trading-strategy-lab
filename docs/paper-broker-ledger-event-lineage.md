# Disconnected ledger event lineage vs broker UNKNOWN inventory

This is an **offline, read-only, caller-declared diagnostic** for PR #152. It does not read SQLite, contact a broker, create or release orders, change risk reservations, or authenticate provider receipts. All execution/clearance flags are always false. Never feed the output into a trade authorization path.

The function inspect_declared_ledger_event_lineage(expected, ledger_summary, events, prior_ledger_tip_sha256) consumes the complete ordered event stream **from genesis** of the v1 ledger in PR #148, the existing inspect_ledger-shaped summary, a separately retained prior tip, and the UNKNOWN intents from the broker census. inspect_declared_ledger_event_inventory_bridge additionally reruns the existing broker census, snapshot replay/chain, snapshot/context anchors and summary bridge before applying the event lineage check. It returns a candidate only if all checks agree; that candidate is still unauthenticated.

Each event uses the exact nine fields seq, broker, account, order_id, event, evidence_sha, recorded_at_ms, prev_hash, event_hash. The v1 event hash is SHA-256 of compact ASCII JSON [1, seq, broker, account, order_id, event, evidence_sha, recorded_at_ms, prev_hash], matching PR #148. This audit requires a contiguous sequence beginning at 1, zero genesis hash, monotonic timestamps, correct hash links, exact summary tip/count/projection, legal PREPARED -> ATTEMPT_UNKNOWN -> terminal transitions, unique account-scoped intents/receipts, and at most one outstanding UNKNOWN per account. It compares the ledger's original intent fingerprint to each expected UNKNOWN intent and requires the recorded UNKNOWN transition to precede the declared attempt by **no more than 60 seconds**. A different adapter contract or legitimate longer delay must be reviewed separately; never silently widen the window.

Strict schema/transition/hash errors raise ValueError (fail closed). Declared tip, timestamp, projection, intent or UNKNOWN timing discrepancies return HOLD_RECONCILIATION with named failed_checks. The event population is capped at 10,000. The diagnostic does not mutate its inputs. A match does **not** establish that the caller supplied all real events, that a local hash chain was independently anchored, that a broker snapshot was complete, or that a receipt came from the provider. A forged event stream can be self-consistent; independent source-of-truth and secure custody remain mandatory.

## Required future integration

PR #148 currently exposes only inspect_ledger's summary, **not** a reviewed read-only event export. This module intentionally does not import PR #148 or bypass its SQLite storage safeguards. A future provider-independent, transactionally consistent, bounded, read-only export must be reviewed on PR #148, including private file checks and an independently secured tip. Then authenticate broker account/order/fill receipts and pagination, reconcile original intents and durable UNKNOWN reservations, verify protective stops, margin/position loss, quote freshness, reconnect quarantine and per-order human authorization. Trading 212's documented API does not support CFDs; do not infer CFD support from this diagnostic.

This PR remains draft and must not be merged or deployed until full exact-head CI and independently verified production backup restoration, rollback and authenticated health gates pass. No profitability claim.
